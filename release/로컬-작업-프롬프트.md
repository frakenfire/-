## 0. 어느 저장소를 받아야 하나

같은 코드가 **두 곳**에 있습니다. 목적이 다르니 하나만 고르세요.

| 저장소 | 주소 | 브랜치 | 앱 위치 | 언제 쓰나 |
|---|---|---|---|---|
| **`frakenfire/-`** | https://github.com/frakenfire/- | `main` | **루트** | ✅ **출시 작업은 여기서** — 앱만 들어 있어 clone 하면 바로 `npm install` |
| `frakenfire/skills` | https://github.com/frakenfire/skills | `claude/today-mind-card-prd-kr7upb` | `tomorrow-note/` | 작업 이력이 남는 원본. 여러 프로젝트가 섞여 있음 |

두 곳은 `git subtree` 로 같은 내용을 유지합니다. **로컬 출시 작업은 `frakenfire/-` 하나만 받으면 됩니다.**

> 로컬에서 고친 걸 `frakenfire/-` 에 push 하면 `frakenfire/skills` 쪽은 그대로 남습니다.
> 둘을 계속 맞추고 싶은 게 아니라면 **신경 쓰지 않아도 됩니다** — 출시는 `frakenfire/-` 만 보면 돼요.
> (굳이 맞추려면 skills 쪽에서
> `git subtree pull --prefix=tomorrow-note https://github.com/frakenfire/-.git main`)

> ⚠️ 두 저장소 모두 현재 **public** 입니다. 출시 전까지 비공개로 두고 싶으면
> GitHub → Settings → General → Danger Zone → Change visibility 에서 private 으로 바꾸세요.
>
> ⚠️ `frakenfire/-` 는 이름이 하이픈 한 글자라 주소가 `github.com/frakenfire/-` 입니다.
> 헷갈리면 GitHub 에서 `todaynote` 같은 이름으로 rename 해도 됩니다(주소만 바뀌고 내용은 그대로).

## 4. 실기기 확인 — 붙여넣을 프롬프트

여기서부터가 **원격에서는 절대 못 했던 부분**입니다. 반드시 본인 폰으로 해야 합니다.

```
빌드해서 실기기에서 볼 준비를 해줘.

1. npm run verify 로 전부 통과 확인
2. npm run audit 으로 전 화면 클릭 점검 (playwright 필요하면 안내대로 설치)
3. npx ait build 로 .ait 번들 생성

그 다음 개발자센터 QR/샌드박스로 내 폰에서 열 수 있게 하는 방법을 알려줘.
```

폰에서 열었으면 **아래 4가지를 직접 눌러보세요.** 코드로는 검증이 안 되는 것들입니다.

- [ ] **보상형 광고가 실제로 뜨는지**, 그리고 **끝까지 본 뒤에만** 심층 리포트가 열리는지
      → 광고를 중간에 닫으면 **안 열려야** 정상입니다 (열리면 즉시 알려주세요)
- [ ] **결과 카드 저장** → 폰 갤러리에 실제 이미지가 저장되는지
- [ ] **공유하기** → 토스 공유창이 뜨는지 (안 뜨면 문구 복사로 대체되는지)
- [ ] 상단 노치 / 하단 홈바에 콘텐츠가 가리지 않는지

문제가 있으면 이렇게 물어보세요:

```
실기기에서 이런 문제가 있었다: (본 그대로 적기)
어느 화면에서, 뭘 눌렀을 때, 뭐가 나왔는지.
원인을 찾아서 고쳐줘.
```

## 7. 이 저장소에서 쓸 수 있는 명령어

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 로컬 개발 서버 (광고는 mock — 항상 보상 성공) |
| `npm run verify` | 타입체크 + 테스트 38개 + 빌드 + mock광고 가드 |
| `npm run audit` | **실제 브라우저로 전 화면 클릭 점검** (아래 참고) |
| `npm run check:release` | 콘솔 값 3종이 채워졌는지 |
| `npm run check:no-mock` | 운영 번들에 mock 광고 코드가 섞였는지 |
| `npx ait build` | `.ait` 번들 생성 |
| `npx ait deploy` | 심사 제출 |

### `npm run audit` 이 잡는 것
빈 화면 / 안 눌리는 버튼 / 엉뚱한 화면으로 가는 이동 / 44px 미만 터치영역 /
대비 미달 / 가로 스크롤 / 콘솔 에러 / 애니메이션 정지된 웹뷰에서 투명해지는 콘텐츠 /
localStorage 차단 / 자정 넘김 후 어제 데이터가 오늘로 남는 문제 / 데이터 삭제·복원.

처음 한 번은 브라우저 설치가 필요합니다:
```bash
npm i -D playwright-core        # 이미 devDependency 에 있음
npx playwright install chromium
```

**정상 결과는 `통과 94 / 94`** 입니다. 하나라도 ❌ 가 뜨면 그 줄을 그대로 복사해
아래처럼 물어보세요:

```
npm run audit 에서 이게 실패한다:
(❌ 줄 그대로 붙여넣기)
원인을 찾아 고치고, 다시 audit 돌려서 94/94 되는지 확인해줘.
```

> 대비(contrast) 검사는 그라데이션 배경도 실제 색 정지점으로 계산하고,
> 컬러 이모지는 제외합니다. 토스 표준 CTA 색(`adaptiveBlue500` 위 흰 글자, 3.71)만
> 의도적으로 예외 처리돼 있어요 — TDS 를 그대로 따르기로 한 값입니다.
